## 三、开发顺序

顺序原则：先打通「下单 → 支付 → 订单」这条最长链路，再补回收、账户、资金、内容；每批都同时在微信小程序与 H5 两端跑，不把 H5 适配留到最后。

### B0 外壳与数据层（无业务页）

| 项 | 内容 |
| --- | --- |
| 路由 | 先注册 4 个 tab + 登录，其余按批次增量注册；原生 tabBar 隐藏，换 DIY 悬浮胶囊 |
| 主题 | `uni.scss` 只保留 `$gold-*` token；全局背景、字号、圆角统一 |
| 数据层 | `api/` + `USE_MOCK` 开关；`request` 封装；`calcPrice` / `isTradingNow` 纯函数 + `node --test` |
| 组件 | `page-footer`（tabbar）、空态、弹层、卡片、主按钮、金额 `tabular-nums` |
| 图标 | `design/icons/*.svg` → `static/icons/*.png`（81×81，≤40KB），首批 20 个 |
| 验收 | mp-weixin 与 h5 均可编译运行；4 个 tab 可切换；金价 861.42；单测绿 |

### B1 主链路（9 页）

登录 → 首页 → 金币 → 商品详情 → 确认订单 → 收银台 → 订单详情 → 我的订单 → 我的。

- 验收：mock 下走通「选规格 → 算定金 10% → 选券/补贴 → 提交订单 → 支付（H5 假支付宝 / 小程序假微信）→ 回跳订单详情显示结果」；订单四态可切换。
- 依赖：6 个新页中的 3 个交易页先出设计稿（确认订单、收银台、订单详情），确认后再写。
- 注意：实名未完成时下单拦截，本期用 mock「已实名」状态，B3 再接真表单。

### B2 回收（3 页）

我的回收 → 回收申请 → 回收电子合同。

- 验收：回收价 = 金价 − 0.5；履约保证金 10%；合同占位；提交后进「待寄送」状态。

### B3 账户与实名（9 页）

重置密码、支付密码、个人资料、个人实名、企业实名、地址、设置、消息、注销。

- 验收：实名表单校验、地址增删改、消息已读/未读、注销二次确认；未实名用户下单被拦。
- 依赖：B1 的下单拦截逻辑先留接口，本批接真表单。

### B4 资金与营销（11 页）

余额、充值、充值记录、提现、提现记录、银行卡、绑卡、优惠券、补贴、发票、开票。

- 验收：余额支付路径打通；优惠券三态（可用/已用/过期）+ 空态；补贴抵扣定金；提现校验支付密码；银行卡解绑二次确认。
- 注意：优惠券复用 CRMEB 的 `couponListWindow` 交互骨架换肤；银行卡 CRMEB 无独立模块，按 365/378/366 新写。

### B5 内容、粉丝与浏览（11 页）

小店、搜索、分类、收藏、运营中心、百科列表、百科详情、教程、教程详情、客服、粉丝。

- 验收：搜索/分类结果可进商品详情；收藏可取消；粉丝只展示一级邀请与贡献统计；百科/教程富文本正常。
- 依赖：3 个新增浏览页（搜索、分类、收藏）设计稿。

### B6 H5 全站回归（不新增页）

- 320 / 360 / 375 / 390 / 414 / 430 六档无横向滚动；`100vh` 与悬浮 tabbar 在 H5 正常；返回/刷新/直接进详情页不白屏。
- H5 支付宝：mock 收银台 → 跳转占位页 → 回跳订单详情；真实支付宝等后端下单接口。
- 微信小程序：胶囊避让、授权登录、模拟支付。

### B7 还原度验收

- 37 页截图逐页并排，621px × 1.207、±2rpx；6 个新页按同一设计体系验收。
- 双端各跑一遍全链路；交付前清理未注册的 CRMEB 页面与素材。

## 四、依赖与风险

| 项 | 影响 | 处理 |
| --- | --- | --- |
| 6 个新增页无截图 | 不能 1:1 还原 | 先出设计稿（B1 三个交易页、B5 三个浏览页），确认后开发 |
| H5 支付宝真实支付 | 需要后端下单/签名/回调 | 本期只做 mock 收银台与回跳；接口契约先定，后端好了再联调 |
| 微信支付资质 | 小程序内不能真实支付 | 本期模拟；资质下来后替换支付分支 |
| 实名 gate | 未实名不能下单 | B1 先用 mock 已实名；B3 接表单 |
| 优惠券/银行卡「现成」 | 只有 CRMEB 优惠券可复用 | 优惠券换肤；银行卡按截图新写 |
| 图标 | 缺图会影响还原度 | 按批次出 SVG → PNG，禁抠图 |
