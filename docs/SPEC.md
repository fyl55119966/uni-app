## Problem Statement

客户要做的是一个线上黄金现货商城：用户看实时金价、按克重订购投资金条、付定金、补尾款、到店自提或物流收货；也可以把旧金卖回平台，申请回收、寄送或到店、验收后收款。客户只做前端，后端还没就绪，但给了 69 张页面截图和一套品牌素材，要求视觉 1:1、双端可跑、支付流程先能演示。

当前的问题是：截图只覆盖了 37 个页面，下单确认、收银台、订单详情、搜索、分类、收藏这 6 个交易/浏览必需的页面没有设计；支付又受平台限制——微信小程序内不能唤起支付宝，微信支付资质还没下来；H5 可以走支付宝，但真实支付要等后端签名。没有一份把「已经做出来的外壳」和「后面 43 页怎么落」写清楚的规格，开发就会边做边改。

## Solution

用一套 uni-app（Vue2）代码同时编译微信小程序和 H5。先把外壳、主题、计价与交易时段、api/mock 边界做成 B0；再按 B1–B5 逐批实现 43 页，每批双端编译、截图比对；B6 做 H5 全站回归，B7 做逐页还原度验收。

- 视觉：金色设计系统（`$gold-*` token），rpx 布局，按 621px 截图 ×1.207、±2rpx 验收。
- 数据：所有页面只依赖 api 层；api 层背后是 mock，用 `USE_MOCK` 切换，后端好了替换实现不动页面。
- 支付：微信内（小程序 + 微信内置浏览器）一律 mock，页面标「测试环境」；真实支付宝只在外部浏览器 H5；H5 检测到微信时隐藏支付宝入口，提示去浏览器打开。
- 订单：定金 10%、尾款 90%；30 天内提货，逾期定金不退；退款按未发货/已发货未签收/已签收分三档。
- 回收：回收价 = 实时金价 − 0.5 元/克；履约保证金 10%；寄送或到店；验收 99.9%；7 个工作日内打款到余额。

## Implementation Decisions

### 1. 基座与平台

- 基线：CRMEB v5.6.2 的 uni-app 工程（Vue2），保留其请求/缓存/工具能力，但不注册 CRMEB 的 233 个业务页；上线前清理。
- 双端：微信小程序 + H5 同一套代码；H5 用 hash 路由，静态部署刷新不 404；小程序自定义导航，页面避开胶囊。
- 临时 appid：`wx4c41da7578d15a3e`；上线前换客户 appid，列入上线前清单。
- 原生 tabBar 移除，改用悬浮胶囊组件；切 tab 用 `reLaunch`，保证栈干净。
- 当前只注册 5 条路由（4 tab + 登录），其余页面按 B1–B5 增量注册；分包规划：主包 5 页，`sub/auth`、`sub/trade`、`sub/fund`、`sub/content`、`sub/invite` 五个分包。

### 3. 设计系统

- 色板：主金 `#D9A133`、浅金 `#EBC15C`/`#D9A83A`、金底 `#F2D9A0`/`#FBF3E2`；米白 `#FAF7F0`/`#FFF6E5`/`#F7F2E7`；文字 `#1F1F1F`/`#2B2B2B`/`#666`/`#8A8A8A`/`#999`；描边 `#EFE7D6`；成功 `#00A870`；危险 `#E5484D`。
- 圆角 12/16/24rpx，胶囊 999rpx；页面左右留白 30rpx；金额用 `tabular-nums`。
- 只写 rpx；截图按 621px 宽 ×1.207 换算，验收 ±2rpx。
- 渐变按钮：`linear-gradient(90deg, #EBC15C, #D9A133)`；主按钮白字。
- 字体：系统字体，不引入第三方字体；标题加粗、编号用等宽数字。
- 图标：SVG 源 → 81×81 PNG（≤40KB），当前 16 个；金刚区截图是 3D 插画，SVG 只能扁平近似，属于已知偏离。

- 组件只做展示与交互，不直接取数；数据由页面通过 api 层注入。

### 5. 数据与接口

- 所有页面只依赖 `api/` 领域模块，不直接 import mock；这是唯一数据缝。
- `USE_MOCK` 总开关：true 时 api 返回 mock 并模拟 200–400ms 延迟；false 时走 CRMEB 请求封装（token、错误码、登录失效）。
- 当前已实现：`getGoldSnapshot()` 返回金价、交易状态、关闭提示、首页金刚区。
- 规划模块：auth（登录/注册/验证码）、goods（列表/详情/收藏/搜索/分类）、order（确认/创建/列表/详情/取消/退款）、pay（下单/查询/回调占位）、recycle（申请/列表/合同）、fund（余额/充值/提现/银行卡/券/补贴/发票）、content（百科/教程/运营中心/客服）、fans（收益/明细/邀请码）。
- 返回统一为整理后的领域对象；页面不碰原始响应字段。
- 金额一律用「分」还是「元」：本期沿用元 + 两位小数，接口层统一 `round2`；后端联调时若返回分，在 api 层转换。
- 登录态：mock token 存本地；请求 401/登录失效码时清 token 并跳登录。

### 6. 业务规则

| 规则 | 口径 |
| --- | --- |
| 总价 | 克重 ×（实时金价 + 工费），四舍五入到分；工费后台配置，演示 100 元/克 |
| 定金 | 总价 ×10%，四舍五入到分；尾款 = 总价 − 定金 |
| 提货期限 | 定金支付日起 30 天内；逾期定金不退；未提货可退定金 |
| 退款 | 未发货：定金+尾款全退；已发货未签收：扣实际运费+保价后退；已签收：走售后 |
| 券/补贴退回 | 券退回原券、有效期不变、过期不补；补贴退回账户、仍限抵定金、30 天有效、不重置 |
| 补贴使用 | 仅抵定金、不可提现、不结转、不找零；先于券抵扣 |
| 优惠券 | 先抵定金，超出部分结转尾款；过期作废；与补贴合计不超订单总额 |
| 回收价 | 实时金价 − 0.5 元/克 |
| 履约保证金 | 回收总额 ×10%；验收后释放；成色不足按实测差额扣；超期/虚假申报扣全部 |
| 回收打款 | 验收通过后 7 个工作日，打入余额 |
| 回收渠道 | 寄送（客户承担运费+保价）或到店（运营中心） |
| 返佣 | 实付总额（定金+尾款）×0.15%；订单完成 T+1 入余额；退款撤销未结算、已结算扣回 |
| 邀请奖励 | 邀请人 10 元、好友 5 元；仅一级直接邀请；好友充值并下单后发放 |
| 邀请码 | 注册页选填，填了即绑定；链接预填；注册后不可改、不可补绑 |
| 提现 | T+1 到账、无手续费、单笔最低 100 元、到银行卡、校验 6 位支付密码 |
| 充值 | 金额任意输入；单笔 ≤5 万走支付宝；>5 万走大额转账（对公+凭证） |
| 实名 | 未实名可浏览；下单/回收拦截；个人+企业；提交后审核中，mock 2 秒通过 |
| 发票 | 只选已完成订单提交；不采集抬头/税号/邮箱；状态四态由客服后台推进 |
| 客服 | 在线客服 9:00–21:00 + 四类 FAQ；不做电话，不接真实 IM |

### 7. 状态机

- 订单：待付定金 → 待付尾款 → 待提货 → 已完成；旁支：已取消、退款中、已退款。
- 回收：待寄送 → 运输中 → 验收中 → 已完成；异常：验收不通过、违约扣保证金。
- 优惠券：未使用 → 已使用 / 已过期。
- 发票：已提交 → 发票已开 → 客服已发送。
- 实名：未提交 → 审核中 → 已通过 / 已驳回。

### 8. 支付矩阵

| 场景 | 可用方式 | 本期行为 |
| --- | --- | --- |
| 微信小程序内 | 微信支付（待资质） | 全部 mock：1 秒后成功/失败，标「测试环境」 |
| 微信内置浏览器 H5 | 无真实支付宝 | 隐藏支付宝入口，提示右上角在浏览器打开；可走 mock |

## Testing Decisions

### 测试缝

- **主缝：api 领域模块**。页面只调 api；mock 与真实实现都从这里进。测试在 api 边界用固定 fixture 验证返回结构，不 mock 页面内部。
- **辅缝：纯函数**。计价、定金、回收价、交易时段、券/补贴分摊、返佣、退款分档都是纯函数，直接单测。
- **UI：人工比对**，不做自动化截图对比；按 621px×1.207、±2rpx 并排验收。
- 默认按以上三条执行；若客户/后端希望加接口契约测试或 E2E，再单独提案。

### 单元测试

- 现有：16g×(869.41+100)=15510.56；定金 1551.06；回收 860.92；交易时段边界 09:29/09:30/23:30/23:31 与周日。
- 计划：券先抵定金、超额结转尾款；补贴不结转不找零；券+补贴不超总额；返佣 0.15% 与退款扣回；回收保证金 10% 与违约扣减；提现最低 100；退款三档。
- 原则：只测外部行为（输入→输出），不测实现细节；金额断言到分。

### 接口测试

- 每个 api 模块至少一个「成功」与一个「登录失效/空数据」用例；mock 延迟可注入 0，保证测试快。
- 页面不直接 import mock 作为验收项；新增页面时用 grep 检查。

### UI 与验收

- 双端编译：`h5` 与 `mp-weixin` 均无报错；小程序能打开 4 个 tab，H5 能直达任意路由。
- 宽度：320/360/375/390/414/430 无横向滚动；`100vh` 与悬浮 tab 正常。
- 还原度：37 页截图逐页并排；6 个新页按同体系检查字号、间距、颜色、圆角。
- 全链路：选规格 → 算定金 → 选券/补贴 → 提交 → 支付（mock）→ 订单详情 → 补尾款/提货。
- 每批完成即跑 `node --test`，并把截图与结论写进批次记录。
